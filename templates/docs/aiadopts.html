Clients & Users › Client ID & Users

Client ID & Users

Every user in AI Adopts belongs to a Client (organization). The ClientUserInfo model is the central governance record that controls what each client's users can see and do.

Core Concept

A Client is an organization that subscribes to Library Bot. A User is an individual within that client. User-level access and feature visibility are both derived from the client's configuration.

📌 Key Rule: Users are always scoped to their client. Cross-client data leakage is prevented at the queryset level in all APIs.

User Identity Resolution

When a user makes a request, the following resolution happens:

1
Auth Token → User

Bearer token resolves to a user identity

2
User → Client mapping

Via User.get_client() → ClientUserInfo

3
Client → LibraryBotConfig

Feature flags, buttons, permissions resolved

4
Context passed to frontend

userInfo object consumed by UserContext provider

Client User Information API

GET /api/v1/accounts/client-user-information/

Resolves client config, feature flags, and the LibraryBotConfig for the authenticated user's client. Called on app bootstrap.

UI Impact: Determines which buttons show, whether login is required, which bots are available, and feature visibility (AI Pulse, Leaderboard, Transform IQ).

Response (key fields)

FieldTypeDescription
client_namestringClient identifier used in API calls
member_emailsarrayAll user emails in this client
libraryBotConfigobjectFeature flags, bot config, UI controls
collectionsarrayCurated concept collections for this client

User Account API

GET /api/v1/accounts/

Returns user identity and client mapping. Used by UserContext to populate the user object across the application.

Adding & Removing Users

✅ How it works: Users are associated with clients via the member_emails field on ClientUserInfo. When a user's email matches a client's member list, they gain access to that client's Library Bot configuration.
ActionMechanismEffect
Add UserAdd email to member_emails in ClientUserInfo (admin)User gains access to client's Library Bot
Remove UserRemove email from member_emailsUser loses access
Feature toggleUpdate libraryBotConfig flagsChanges UI buttons, visible sections, bot availability

Tenancy › Concept of Tenants

Concept of Tenants

AI Adopts is a multi-tenant platform. Every client (organization) is an isolated tenant — they share the same codebase and infrastructure but have completely independent data, configurations, and user bases.

What is a Tenant?

A tenant maps directly to a Client in the system. The tenant is resolved from every authenticated request via middleware, ensuring strict data isolation.

🔐 Tenant Resolution Flow: Auth Token → Middleware → Client/Tenant context → All querysets automatically scoped

Tenant Isolation Rules

LayerIsolation Mechanism
DataAll querysets filtered by client/tenant identity
UsersUsers scoped via member_emails on ClientUserInfo
Course PackagesEach CoursePackage FK'd to a ClientUserInfo
ReportsAI Pulse & Leaderboard scoped to client members only
Company IQapproved=True + deleted=False enforced globally
CoachBotbotId sourced from client-specific config

LibraryBotConfig — Tenant Feature Flags

The LibraryBotConfig model controls the exact experience each tenant gets. It is the primary feature-gating mechanism.

bot_configJSONWhich CoachBot(s) are available, their IDs and modes
show_ai_pulseBooleanWhether AI Pulse report section is visible
show_leaderboardBooleanWhether Leaderboard report is visible
leaderboard_report_protectedBooleanWhether Leaderboard requires a password
show_transform_iqBooleanControls Transform IQ section visibility
button_controlsJSONFine-grained button show/hide rules per action tab

CoursePackage — Tenant Content Bundles

Each tenant gets one or more CoursePackages — client-specific bundles of courses. A package is the top-level unit that users see in the Library UI.

CoursePackage · page_config example
{
  "show_filters": "Industry, Function, Business Outcome",
  "show_lists": true,
  "show_search": true
}

The page_config JSON drives which filters and controls appear on the Library page — different per client, without code changes.

Tenant API Pattern

All tenant-aware APIs follow the same pattern:

1
Auth token verified

Middleware validates and extracts tenant identity

2
Queryset scoped

deleted=False + tenant FK filters applied at ORM level

3
Soft deletion respected

No hard-deletes — records marked deleted=True are invisible

4
Response serialized

Public serializer strips admin-only fields before response

Tenancy › Login vs No-Login Tenant

Login vs No-Login Tenant

AI Adopts supports two distinct tenant access modes: authenticated (login required) and public (no login). These modes determine what features are available and how progress/analytics are tracked.

Access Modes

FeatureLogin TenantNo-Login Tenant
User identity✅ Resolved via auth token❌ Anonymous / email-based
Progress tracking✅ Persisted to DB❌ Disabled (onlyClientSetup=true)
Audio tracking✅ played_audio + completion%❌ Not persisted
AI Pulse Report✅ Real member data❌ No member scoping
Leaderboard✅ Ranked by completion❌ Not applicable
JobAid sessions✅ Stored with user email✅ Stored with provided email
IdeaBoard voting✅ User email tracked✅ Provided email tracked
CoachBot✅ Full conversation history⚠️ Limited per config

The onlyClientSetup Flag

The onlyClientSetup boolean prop on BookPageClient is the primary toggle for no-login mode:

TypeScript
// Login tenant (default)
<BookPageClient id="pkg_123" />

// No-login tenant
<BookPageClient id="pkg_123" onlyClientSetup={true} />

Audio Tracking in Login Mode

When onlyClientSetup === false (login mode), audio playback fires a real-time progress update:

POST /api/v1/courses/course-progress
JSON Payload
{
  "user_uid": "user_uid",
  "course_id": "course_uid",
  "module": {
    "module_id": "module_uid",
    "status": "in_progress",
    "completed_in_percentage": 45,
    "played_audio": 30
  }
}

In no-login mode, this API call is skipped entirely — no progress is persisted.

Authentication API

GET /api/v1/accounts/

Used by UserContext to resolve user identity. In no-login tenants, this may return a client-scoped anonymous session rather than a personal user record.

⚠️ For No-Login tenants: JobAid sessions still store an email provided by the user at submission time. This enables basic session tracking without requiring authentication.

UI Blocks & APIs

Library Bot renders as a single orchestrated workspace with five primary content sections (UI blocks). Each block maps to a backend component, a set of APIs, and an actionKey that drives navigation.

1. Concepts / Collections

ConceptsViewer Read-only Curated

High-signal knowledge anchors — curated thinking tools, not user-generated content. Renders PDF iframes, HTML embeds, and Transform IQ links grouped into Collections.

How it works

Each Collection has action_tab_info JSON that defines buttons and their action keys. These actions match CaseMappings.action_name, which opens the embedded content.

action_tab_info example
{
  "id": "design-architecture",
  "title": "Design & Architecture Guardrails",
  "description": "Evaluation Heuristics for common cases",
  "buttons": [{
    "label": "ALIGN",
    "Collection_name": "collection_name",
    "heading": "Section heading override",
    "action": "DESIGN_ARCH_GUARDRAILS"
  }]
}

Data Source: userInfo.collections → collection.case_items

2. Cases / Modules (Books)

BookSection Audio Progress Likes

The core library experience. A "Book" is a Module that can contain audio, video, text, assessments, or chatbot interactions.

How the Dashboard Connects to AI Adopts

Every visible element in the Library Bot UI traces back to a record in the Django admin. The diagram below shows the chain of control:

Control chain
Django Admin
│
├── ClientUserInfo          → Who can log in & what client they belong to
│   └── LibraryBotConfig    → Which sections / buttons / bots are ON or OFF
│
├── CoursePackage           → What content bundle the client sees
│   └── Course → Module     → Individual learning units (books, audio, tests)
│
├── Collection + CaseMappings → Concepts tab content (PDFs, iframes)
│
├── JobAid + JobAidQuestion → Purpose tab form definition
│
└── CompanyIQ               → Landscape tab company records (approve/reject)
✅ Golden rule: If something is not showing up in AI Adopts, the first place to check is always the Django admin — a missing FK, an approved=False flag, or a missing config field covers 90% of issues.

Client & User Management

Go to Admin → Accounts → ClientUserInfo

Creating a New Client

1
Add a ClientUserInfo record

Set client_name — this becomes the tenant identifier used in all APIs. Must be unique and lowercase-friendly.

2
Add member emails

Paste all user emails into member_emails. These are the only emails that will resolve to this client on login.

3
Link a LibraryBotConfig

Create or assign a LibraryBotConfig record. This is what gates every UI feature. Without it, the Library Bot loads with all features OFF.

4
Link a CoursePackage

Assign the content bundle for this client. The package controls which courses and modules they can access.

5
Assign Collections (optional)

Add curated concept collections for the Concepts tab. Without these, the Concepts section will be empty.

Adding & Removing Users

ActionWhere in AdminField to editEffect
Add a userClientUserInfo → editmember_emails — append emailUser gets access on next login
Remove a userClientUserInfo → editmember_emails — delete emailUser loses access; excluded from AI Pulse & Leaderboard reports

⚠️ Important: member_emails is also what scopes the AI Pulse Report and Leaderboard. If a user's email is missing from the list, they won't appear in any analytics even if they're using the platform.

Company IQ — Approval & Data Management

Go to Admin → Company IQ → CompanyIQ

Company IQ records are never visible in the frontend until explicitly approved by an admin. This is the main content gate for the Landscape tab.

Approving a Company Record

StepFieldNotes
1. Open the record—Find by company name or filter by approved=False
2. Review dataAll JSON fieldsCheck ai_use_cases, cloud_tech_stack_signals, transformation_iq_outlook for accuracy
3. Set approvedapproved = TrueRecord is now live in the Landscape tab immediately
4. Set sourcesourceManual / CSV / LLM — for auditability
⚠️ Duplicate protection: The system blocks creation of a second record with the same normalized company name. If you try to create "Google" when "google" already exists, it will be rejected at save time.

Soft-deleting a Company Record

📌 Never use Django's delete button for CompanyIQ records. Set deleted=True instead. Hard-deleting breaks historical references. The record stays in the DB but disappears from all API responses immediately.

JobAid Management

Go to Admin → Job Aid → JobAid and Admin → Job Aid → JobAidQuestion

JobAids define the Purpose tab experience. A single JobAid can be a form, a structured report generator, or a prompt builder — controlled entirely by field flags.

Creating a JobAid

FieldValue to setEffect
job_aid_typejob_aid / form / prompt_generatorDetermines the UI flow and output type. form disables AI validation automatically.
is_validationTrue / FalseIf True, each answer is AI-validated before user can proceed to next question
is_reportTrue / FalseIf True, submission generates a structured AI report with a shareable URL
is_prompt_generationTrue / FalseIf True, submission generates a reusable AI prompt instead of / in addition to a report
evaluate_jobaidTrue / FalseIf True, an Innovation Score or evaluation score is computed and injected into the session QnA
session_voting_enabledTrue / FalseIf True, sessions from this JobAid appear in the IdeaBoard (View tab) and can be voted on
validation_promptLLM prompt stringSystem prompt used to validate answers. Should instruct the model to return ACCEPTABLE / NOT ACCEPTABLE + suggestions.
report_generation_promptLLM prompt stringSystem prompt used to generate the final report from all QnA data
report_header / report_footerText / HTMLWraps the AI-generated content in the rendered report page

Adding Questions to a JobAid

Go to Admin → Job Aid → JobAidQuestion, create questions linked to the JobAid.

FieldOptionsNotes
question_typetext / dropdown / booleanControls the input widget shown to the user
dropdownsComma-separated stringE.g. "Strategy, Operations, Finance, HR" — rendered as a dropdown menu
is_multi_selectTrue / FalseFor dropdown type — allows selecting more than one option
allow_custom_textTrue / FalseAdds a free-text "Other" input below the dropdown
attachment_allowedTrue / FalseEnables file upload on this question
sectionString labelGroups questions under a section heading in the form UI
validation_promptLLM promptQuestion-level override — runs instead of the JobAid-level prompt for this specific question

Typical New Client Setup Checklist

1
Create ClientUserInfo

Set client_name, add member_emails

2
Create LibraryBotConfig

Set feature flags, bot_config, button_controls. Link to ClientUserInfo.

3
Create or reuse Courses + Modules

Courses are reusable across clients — only Packages are client-specific.

4
Create CoursePackage

Link client, courses, job_aid, page_config. This is what the Library page loads.

5
Create Collections + CaseMappings

Link Collections to ClientUserInfo for the Concepts tab.

6
Approve CompanyIQ records

Filter by industry/source, review, set approved=True.

7
Create JobAid + Questions

Link JobAid to CoursePackage.job_aid for the Purpose tab.

8
Test in Library Bot

Open /library/:packageId as a member user and verify all tabs load correctly.
